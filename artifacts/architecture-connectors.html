04 / 11

Hard rules (spec.md)

  • base integrity over features — the invariants are the product
  • one seam — phone ⇄ proxy only; tailnet is the boundary
  • opencode is the source of truth for sessions (this rule changes with connectors)
  • local-first — speech on LAN, no cloud speech APIs
  • degrade, don't break — bounded silent retries, log-only diagnostics, no auto-fix loops

Path to one-click ready PWA (Android)

spec: docs/spec-onboard.md — the goal: link + one phrase → working stack; phone scans one QR

1 · bootstrap.sh

fresh VPS or own box: mints every secret, generates configs, starts the stack — zero judgment calls (phase 1: shipped, cross-harness proven)

→

2 · /pair QR

terminal prints a QR — phone camera pairs: URL + config + push registration, no typing (concept → build)

→

3 · install

Android: browser menu → install app → home-screen icon, standalone, theme; iOS: Safari → Add to Home Screen

  • skill-driven: any harness (opencode / Claude Code / Codex) can run the install from the raw SKILL.md link — proven on cold containers + real hardware
  • one manual step by design: opencode auth login — your LLM key is the one thing no bootstrap may mint
  • update story: same skill, section 5 — git pull + idempotent bootstrap, secrets persist

Your plugins stay yours

concept (name reserved: local plugins) — user-owned extensions that never leave the instance

  • gitignored plugins/ dir next to the instance config — created empty by bootstrap, survives every update
  • loaded by the proxy seam — route hooks / middleware list, same trust boundary as the seam itself
  • never upstream: your plugin folder is not in the repo, not in releases, not in issues — it is yours
  • open shape decision: connector-contract plugins vs UI/route extensions vs both
