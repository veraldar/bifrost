# MINI-AGI / halo-memory — research report

*Reconstructed 2026-10-04 from disk + git state. No files were modified; this report only.*

## 1. What the project actually is

**Not a from-scratch AGI build.** It is a toy-scale *validation experiment* — `experiments/halo-memory/` — asking one question:

> Can a continuously-trained LM over a session ledger provide *associative recall* that exact retrieval (grep/BM25/RAG) cannot, without catastrophic forgetting?

The name "mini-AGI" comes from a YouTube video that inspired it — **provenance confirmed**:

> **Source:** ["This Tiny AI Never Stops Learning (mini-AGI)"](https://www.youtube.com/watch?v=L-6O7R71CCg&t=429s) — BetterStack (Andrus), fetched 2026-10-01, full ~2,400-word transcript saved at `artifacts/yt-transcript-miniagi.md`. Live-page title verified 2026-10-04.

That video's mini-AGI is a toy-scale continual-learning MoE with a "slow trunk", claiming 99.84% retention under a chess-only data flood. The local experiment **replicates that slow-trunk finding at toy scale** to decide whether it's worth renting a GPU for the real thing.

**Important correction to the memory of it:** the model was never going to be "an AGI trained on bifrost session data". The corpus is **synthetic** (generated by `gen_corpus.py`, styled to *look like* bifrost session notes — topics include "bifrost", "voice-agent", "homelab"). Replaying real bifrost exports was explicitly deferred to "a second pass" (README, last section).

## 3. Intended methodology, reconstructed from the video (§3.0) and the code (§3.1)

### 3.0 What the source video prescribes (transcript, artifacts/yt-transcript-miniagi.md)

The video's mini-AGI (author's repo, only ever tested on Nvidia; demoed on an M2 Max MacBook) is:

1. **Blank start, letter-by-letter.** A model that knows nothing, reading text byte by byte; you can teach it anything, not just language (demo: TinyStories → English in ~2–4 h; then Tarantino screenplays for style).
2. **Never stops training.** Text read *in order*, one chunk at a time, one small gradient step per chunk, no finish line — continual learning as a lifestyle, not a phase.
3. **Mixture-of-Experts as disk workspace.** Each expert is its own file on disk; before each chunk only the experts that text needs are loaded, so the model can exceed GPU memory. Experts spawn and get pruned by usage — a self-governing workspace.
4. **The slow trunk (the load-bearing trick).** A shared core every letter passes through; experts train fast, the core updates ~10× slower. Author's catastrophic-forgetting test: model knowing 8 subjects fed half a million chars of chess → normal setup loses ~half of everything, mini-AGI keeps **99.84%**. New knowledge lands in specialists; the foundation stays put.
5. **Held-out eval + recovery dynamics.** One script (Reservoir Dogs) hidden for eval; observed: improvement on hidden script stalls (~15 min) while visible data gets memorized; switching back to old data recovers fluency in ~5 min — "knowledge was never erased, it was already on disk."

### 3.1 How the local experiment maps onto it

| Video element | Local replication in halo-memory |
|---|---|
| Slow trunk / experts split | `frozen` arm: embeddings + all attention blocks frozen while reading new topics (exact-slow-core analog); `interleaved` arm replicates the "revisit old data" behavior |
| Continual learning, old → new | Phase 1 on old-topic stream → Phase 2 arms on new topics (massed = the "chess flood" that should cause forgetting) |
| Hidden held-out eval | Held-out old-topic sessions for loss (H1); hidden alias-A target sessions for association ranking (H2) |
| "Never stops" ordering | Simplified away — arms train in shuffled windows, not in-order streaming (a deliberate reduction; see §7 caveat 4) |
| MoE / expert files on disk | **Not replicated** — out of scope at 2.6M params; the experiment tests the *memory* claim, not the MoE mechanics |
| "AGI" branding | Dropped deliberately — the README frames it as an associative-recall test with preregistered failure modes |

What the local experiment adds that the video doesn't have: a **retrieval-null hypothesis**. The video only shows the model not forgetting; halo-memory asks whether weights-as-memory can *beat grep at something grep structurally can't do* (alias-A ↔ alias-B linkage with zero surface overlap), with chance rates, decoys, and a hallucination-cost metric (H4).

## 4. What the code does

### Data pipeline (`gen_corpus.py`, seed 7, ~430K chars)
- 8 topics (6 "old" + 2 "new" for retention arms), ~6,400 filler sessions + **80 planted concepts**.
- Each concept: an early **target** session (decision about alias A) and a late **probe** session about the same referent under **alias B** — zero shared content words. E.g. target: *"decided the plot loop should use firmware instead of the old path"*; probe: *"the elo job cut-off again right before the bewildering"*.
- 40% of concepts get **bridge** sessions (explicit rename notes — retrieval *should* solve these); 60% are **unbridged**, linked only through noisy co-mention sessions.
- 9 same-topic decoys per probe → chance hit@1 = 0.10. Everything seeded, ground truth fully controlled.

### Baselines (`baselines.py`) — already run, results in README
```
all:        grep hit@1=.062  bm25 .062  grep1hop .075   (chance .10)
unbridged:  grep .038  bm25 .058  grep1hop .077
```
Exact retrieval fails **by construction** (no mechanism to link alias A→B); below chance because same-topic decoys share the probe's lexicon. Headroom to detect a real effect exists.

### Model (`train_halo.py`)
- Char-level transformer, **~2.6M params**: 4 layers, d=128, 4 heads, ctx=256, learned positional embeddings, CPU-only.
- **Phase 1**: base training on old-topic stream (2,500 steps).
- **Phase 2**, three arms from the same base checkpoint (1,200 steps each, lr×0.5):
  - `massed` — new topics only → old knowledge should degrade;
  - `interleaved` — new + ~10% old mixed → should retain (mini-AGI's finding);
  - `frozen` — new only, embeddings+all blocks frozen → slow-trunk analog.
- **Evals**: held-out old-topic loss (H1 retention), association ranking hit@1/MRR primed-on-probe→rank-target-vs-decoys (H2), bridged/unbridged split (H3), decoy false-positive rate (H4 hallucination cost).

### Decision rule (README)
- interleaved retains loss AND hit@1 ≫ 0.10 → halo adds real associative recall → justify GPU rental to scale up.
- retention but chance-level association → remembers domains, not referents → negative for memory use.
- association but high decoy FP → usable only as hints, never facts.

## 6. What it would take to continue

**Compute: trivial.** It's 2.6M params, CPU-only, ~430K chars. One full run = 2,500 + 3×1,200 steps at bs=24, ctx=256 — order of tens of minutes to a couple of hours on this box, not GPU time. Resuming is one command:
```bash
cd experiments/halo-memory && .venv/bin/python train_halo.py --seed 0 --out results/results_s0.json
```
Then repeat for a couple more seeds (the code takes `--seed`) and compare against the README baselines. If the interleaved arm passes the decision rule, the "next step" is a real-data pass (replay actual bifrost session exports) and only after that a GPU-scaled version — i.e., the actual "mini-AGI on bifrost data" the user remembers would be phase 2/3, never started.

## 7. Honest assessment

**Sound:** controlled synthetic ground truth; baselines that fail by construction (a real gap to measure against); preregistered decision rules including the negative outcomes; toy-scale replication *before* renting GPUs is exactly the right economics. Code quality is fine — small, seeded, reproducible, obvious CLI.

**Caveats to keep in mind:**
1. **Template regularity is the big risk.** The synthetic corpus is built from ~20 sentence templates; a char-LM can ride template statistics rather than learn alias↔alias association. A pass here would be encouraging but weak evidence; a fail would be ambiguous (can't distinguish "association doesn't emerge at 2.6M params" from "task is learnable by shortcut but the model is too small/dumb").
2. **Scale gap is huge.** 2.6M char-level vs the video's 559M MoE. Char-level ctx=256 over 430K chars is ~1–2 orders of magnitude less "experience" per concept (80 concepts → ~5 probe/target pairs each) — plausibly too few examples for the effect to clear noise. Multiple seeds are mandatory, not optional.
3. **It is not — and was never going to be — AGI.** Even the inspiring project is described by its own author as toy-scale, "hell no" not AGI. The realistic ceiling of this line of work is a *hint engine* (ranked associations to feed a retrieval/agent system), which is genuinely useful for bifrost but should not be sold to oneself as model-building toward AGI.
4. **Continual-training framing vs the actual test:** the arms test retention, but the association eval is done per-arm on a model that has seen the whole ledger in random windows — order, recency, and "when did the probe arrive" play no role. That's fine for H2, but it means a pass wouldn't yet demonstrate *continual* acquisition of associations, only that they can be stored.

**Bottom line:** the project is a well-designed, half-finished afternoon experiment — everything through baselines done, training aborted at step 0, zero results. It is fully recoverable in one CPU command and one to three hours. Its honest purpose is a go/no-go gate on spending real money on the continual-memory idea, not an AGI build; and it isn't lost — committed at HEAD and replicated across five worktrees.
